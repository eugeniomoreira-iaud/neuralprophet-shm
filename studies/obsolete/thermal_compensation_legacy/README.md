# Study · Temperature compensation on the legacy era, station 02

The same question asked in `../thermal_compensation/`, on different data: does the fixed
thermal correction that `00_Sensor_Preprocessing` applies help or hurt a prediction
system built on the inclinometer signal?

```
I_comp(t) = I(t) − (T_air(t) − T_air(t₀)) · c · 1000,     c = 0.005
```

**The complete evaluation — year selection, decomposition, imputation, results,
figures, interpretation, verdict and caveats — is in
[`report/legacy_compensation_report.pdf`](report/legacy_compensation_report.pdf).**
This file only says how to run and rebuild things.

**Verdict in one line:** the correction fails all three acceptance criteria on a full
calendar year (2021) of the legacy instrument, matching the current-era study from
independent data, a different instrument and a different regressor set.

**Why this study exists.** The current-era study has four environmental channels but
only half an annual cycle. This one has a full calendar year and only two channels
(`tair`, `rh`), which makes the seasonal response observable.

**The finding only a full year could produce.** The inclination reaches its seasonal
maximum on 7 June; air temperature reaches its own on 5 August. **The structure leads
the air by 59 days** (an independent cross-correlation estimate puts the lead at 89).
No thermal lag can represent that — a causal filter delays a driver, it never advances
one — and the scan confirms it: every time constant from 1 to 168 hours makes the
annual fit monotonically worse. At the daily scale, by contrast, instantaneous air
temperature explains 91.5 % of the variance. The two timescales need different
treatment, and a single fixed coefficient serves neither.

**Sampling.** Everything runs on a **1-hour grid**, matching the rate of every external
proxy the pipeline aligns against.

**Figures.** All plotting goes through seaborn; set `CONTEXT = 'paper'` to re-export at
manuscript column size.

**Shared tests.** The acceptance tests, coefficient sweep, slope fitting and forecasting
experiment are imported from the sibling study, not reimplemented. Any difference in
results is a difference in the data, not in the method.

## Reproducing the study

```bash
conda activate neuralprophet_env
cd studies/thermal_compensation_legacy
jupytext --to ipynb legacy_compensation_study.py
jupyter nbconvert --to notebook --execute --inplace legacy_compensation_study.ipynb
```

`lc_lib.py` imports from `../thermal_compensation/tc_lib.py`. Moving or renaming either
folder breaks that import.

## Rebuilding the report

Run the notebook first — the report reads the figures from `outputs/`, which is not
committed.

```bash
cd report
pdflatex legacy_compensation_report.tex   # twice, for the table of contents
```

The shared preamble lives in `../../_shared/reportstyle.tex` and stays inside the
package set shipped with a basic TeX Live installation.
