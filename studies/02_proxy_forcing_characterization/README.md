# Study 2 · The external forcings: air temperature and solar radiation

Two quantities drive the wall, and neither is measured well at the wall itself. Air temperature is
recorded inside the instrument housing, which is a sun-exposed box rather than a meteorological
screen. Solar radiation exists only in the current instrument era, and study 1 condemned 161 of its
days. Everything the project will later ask of a thermal driver therefore depends on external
sources whose agreement with each other, and with the site, has to be measured before any of them
is used.

This study characterises air temperature and solar radiation in each available source, measures how
far apart the sources are, and calibrates them against the one stretch of on-structure radiation
that study 1 certified as trustworthy.

**Status: skeleton.** The folder, the parameters and the library scaffolding are in place; the
analysis is not yet written. This file describes what the study is for and how it will be run.

## The question, in three parts

1. **What does each source say?** Extent, coverage, distribution, annual and diurnal cycle, and
   clock, for `tair` and `sr` in every source that carries them. A source is characterised on its
   own terms before it is compared with anything.
2. **How far apart are they?** Pairwise agreement between the sources, resolved by season and by
   time of day rather than reported as a single correlation. They are not replicates — a housing on
   a sun-exposed wall, a standard screen in town and a nine-kilometre grid average are three
   different quantities that share a name — so the object of interest is the *structure* of the
   disagreement, not its existence.
3. **What does the certified on-structure radiation say about them?** The current-era `sr` channel,
   restricted to the days study 1 did not condemn, is a short but genuinely local measurement. It is
   the only reference that sees the sky the wall sees. Both external radiation sources are scored
   against it over that window, and the result decides which one may stand in for it elsewhere.

## What it reads

| Input | Provenance |
|---|---|
| `../../data/interim/archive/gubbio_archive_20min.csv` | **Study 1's product.** The sensor side: `n_tair`, `n_sr` and the legacy `st0*_tair`, each with its `_flag` and `_ok` companion, plus the `sr_suspect` verdict column |
| `../../data/raw/proxies/oikolab_weather.csv` | ERA5 reanalysis, retrieved through Oikolab by `auxiliary/oiko.py` |
| `../../data/raw/proxies/meteosystem_gubbio.csv` | Ground station in Gubbio town, retrieved by `auxiliary/meteosystem_italy.py` |

Study 1 is a prerequisite: its export must exist before this notebook is run. Nothing here reads
the raw `.adc` archive, and nothing here re-decides a rejection study 1 already made. The `_ok`
columns are taken as given; where this study needs to depart from one, it says so and shows the
recorded value beside it.

**The narrow window.** `n_sr_ok` carries a correction as well as rejections: radiation recorded
while the sun is more than six degrees below the horizon is set to zero, which is the only
unmeasured number in any `_ok` column. On top of that, `sr_suspect` marks 161 days on which the
channel has no diurnal cycle at all. The usable radiation window is what survives both, and
measuring its true extent is the first result this study produces rather than a number it assumes.

## What it writes

Tables and figures into `outputs/`, named `PF_01_*`, `PF_02_*` for tables and `PF_F01_*`,
`PF_F02_*` for figures, which the report reads. Whether this study also exports an aligned
hourly forcing dataset for later studies is deliberately left open until the comparison is done:
the point of the study is to decide which source is fit to be exported, and building the export
before that decision would prejudge it.

## Contents

| File | Role |
|---|---|
| `proxy_forcing_characterization_study.py` | The study, in `py:percent` format. **Edit this one.** |
| `proxy_forcing_characterization_study.ipynb` | Paired notebook, generated by `jupytext`. |
| `report/` | Report source and PDF. |
| `outputs/` | Tables, LaTeX table bodies and figures. Gitignored. |
| `tests/` | Unit tests for the `shmlib` decisions this study relies on. |

This study has no library of its own: source loading and harmonisation, the source and channel
characterisations, the agreement measures, the certified-window census and the radiation
calibration all live in `../shmlib/` — `shmlib.proxies`, `shmlib.quality`, `shmlib.compare` and
`shmlib.figures`, alongside the facts about the site — the eras, the logger's clock, the solar
geometry, the site coordinates — in `shmlib.site` and `shmlib.solar`. `studies/shmlib/` is the
studies' only library; there is no per-study `*_lib.py` tier. This study and study 1 read the same
flag vocabulary and the same site facts from that one place, so the two cannot disagree about where
the sun was or which day was thrown out. Nothing here imports from `../obsolete/`.

## Reproducing

```bash
conda activate neuralprophet_env
cd studies/02_proxy_forcing_characterization
jupytext --to ipynb proxy_forcing_characterization_study.py
jupyter nbconvert --to notebook --execute --inplace proxy_forcing_characterization_study.ipynb
```

Run `auto_watcher.py` from the repository root during a working session and the `.py` and `.ipynb`
stay in sync without the first command.

## Rebuilding the report

Run the notebook first — the report reads figures and table bodies from `outputs/`, which is not
committed.

```bash
cd report
pdflatex proxy_forcing_report.tex   # twice, for the ToC
```

The shared preamble is `../../_shared/reportstyle.tex`.
